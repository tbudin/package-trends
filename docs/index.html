Download trends, small enough for a footer

A package's npm downloads as a sparkline, a line of text, or a KPI block. No dependencies, no stylesheet, and no chart library — 10.5 kB with the React components.

Fetching react from npm…

Live from api.npmjs.org, fetched by this page as you loaded it.

Install

npm install @plainmatter/package-trends
import { PackageTrend } from "@plainmatter/package-trends/react";

<PackageTrend package="react" />                 // sparkline
<PackageTrend package="react" variant="text" />  // 624.9M downloads +4.2%
<PackageTrend package="react" variant="kpi" />   // the number, the change, the chart

Three variants

Render on the server

Fetch once where the page is built and pass it down. No visitor costs a request, and the chart is in the first paint rather than appearing a moment later. 

import { fetchDownloads } from "@plainmatter/package-trends";

const data = await fetchDownloads("react", { period: "last-month" });
return <PackageTrend package="react" data={data} variant="kpi" />;

What it gets right

It repairs the days npm has no data for

The API answers 0 for a day it has not aggregated, and gives you no way to tell that from a day nobody installed the package. A sample of react carried seven of them in thirty. Taken literally they understate the mean by a quarter, invert the weekday profile, and turn a flat month into a fall. Interior gaps are interpolated and listed in gapDays.

Smoothing never touches the numbers

Daily counts swing threefold across the week, so the drawn line is a 7-day mean by default. Every figure beside it — total, average, peak, change — comes from the raw series, so a smoothed chart cannot quietly restate the total.

The smooth curve cannot invent a value

curve="smooth" is monotone cubic, not a cardinal spline. A cardinal spline overshoots a local extreme and draws a count below the real low — below zero, where the low is near it. Between any two points this curve stays within their values.

It takes the colour and size of whatever surrounds it

The chart strokes in currentColor and the type is set in em, so it inherits rather than imposing. Nothing ships a stylesheet. The only two colours it would choose for itself — the rise and the fall — are unset by default and inherit too.

Comparing packages

Four packages on one shared scale, and the same four each measured against their own start. The first is literally true and close to useless.

Reading the data

analyse() returns the figures you would need to write about a package without looking at the chart: a least-squares fit with its r², compound weekly growth, the weekday and weekend split, volatility with the weekly cycle removed, spikes past two standard deviations, and a rising or falling week streak. 

const a = analyse(await fetchDownloads("react", { period: "last-year" }));

a.direction;    // "rising" | "falling" | "flat"
a.confidence;   // "strong" | "moderate" | "weak", from the r²
a.weekendRatio; // 0.61 for react — weekday-driven use

The field to build a sentence on is confidence. A slope alone will cheerfully report that react is falling by 390,000 a day; the r² of 0.05 behind it is what says the month was flat and the slope is noise.
